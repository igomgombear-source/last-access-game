# last-access-game

마지막 접속 v13 · 첫 구현본

공개 GitHub 저장소에서 관리하는 프로젝트입니다. HTTPS 전체 플레이 검증은 아직 완료하지 않았습니다.

## 변경 범위

챕터 B의 ‘11월 1일 마지막 만남’(BP5)에 진술·증거 대조를 추가했습니다. 사진과 직접 목격 기록 모두 근거로 인정합니다. 일정과 자동 동기화는 실제 만남의 근거로 인정하지 않습니다. 단계별 힌트와 원문 비교를 제공합니다.

인물, 기록 원문, 사건, 결말을 변경하지 않았습니다. 기존 JavaScript 4개, CSS 3개, 이미지 등 26개 파일은 v12와 바이트 단위로 동일합니다. 추가 기능은 `site/deduction-v13.js`, 스타일은 `site/deduction-v13.css`입니다. `index.html`에는 해당 파일 참조와 버전 제목만 변경했습니다.

이 버전은 전체 v13 개발 설계의 첫 단계입니다. 새로운 자백·해명·엔딩을 추가하지 않았습니다.

## 저장 호환

기존 저장 형식과 키를 유지합니다. 같은 사이트 주소에 배포하면 v12 저장을 이어서 사용하도록 설계했습니다. BP5를 이미 해결한 저장은 다시 풀도록 강제하지 않습니다. 새 증거 선택도 기존 자동·수동 저장 상태에 포함됩니다. HTTPS에서 실제 저장 복구 검증은 아직 남아 있습니다.

Netlify에서 GitHub Pages로 주소가 바뀌면 브라우저 저장은 자동으로 이전되지 않습니다. 원래 주소의 저장 데이터는 삭제되지 않습니다.

## 검사

`node checks/check.mjs`는 구문·파일·기존 파일 보존과 새 판정 함수만 검사합니다. 로컬 웹 서버나 게임 화면을 실행하지 않습니다.

작업본 정적 검사 108개, 새 판정 사례 11개, 기존 파일 26개 보존 검사를 통과했습니다. 이것은 전체 게임 플레이 통과를 뜻하지 않습니다.

## GitHub 등록과 배포

1. 업로드할 계정과 공개 저장소를 정합니다. 이 폴더 내부를 저장소 루트에 업로드합니다. 숨김 `.github` 폴더도 포함해야 합니다.
2. 이 공개 저장소는 GitHub Free에서도 Pages를 사용할 수 있습니다.
3. 게임 사이트 공개 여부를 결정한 뒤 Settings → Pages에서 GitHub Actions를 배포 소스로 선택합니다.
4. Actions → Validate and deploy game → Run workflow를 실행합니다. 자동 배포는 설정하지 않았습니다.
5. 배포가 성공한 HTTPS 주소에서 아래 회귀 검사를 수행합니다.

공식 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages
