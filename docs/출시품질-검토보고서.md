# 《마지막 접속》 출시 품질 검토와 수정 기준

검토 기준일: 2026-11-06 · 대상: GitHub Pages의 v13 첫 구현본

실제 실행 주소: https://igomgombear-source.github.io/last-access-game/

## 검토 결과

기존 배포본을 실제 HTTPS에서 TRUE END까지 다시 진행했다. A 필수 7개와 선택 3개, B 필수 6개를 완료했다. 암호 오답과 재입력, 일반 추리 오답, BP5 불충분 근거와 사진·목격 두 정답 경로, 수동 저장·불러오기·취소, 자동 저장 후 새로고침 복구, 최종 인물 오답과 재시도를 확인했다. 확보한 게임 콘솔 오류·경고는 빈 목록이었다.

기능적으로 끝까지 갈 수 있는 단편이다. 상업용 추리 게임으로 보강해야 할 핵심은 조사하게 되는 이유, 자료를 스스로 해석하는 경험, 반복되지 않는 조작, 개인 휴대폰의 현실감이다. 단서 수를 늘리기보다 기존 단서가 플레이어의 판단을 바꾸는 과정을 강화한다.

이 평가는 한 번의 주요 전체 경로와 일부 재시도에 근거한다. 모든 분기와 실기기·모든 브라우저를 검사한 결과가 아니다. 상업적 성공이나 일반 플레이어의 재미가 입증됐다는 뜻도 아니다.

## 소스 감사에서 추가 확인한 문제

아래 항목은 전체 플레이 관찰과 별도로 소스의 기록·판정 관계를 검토해 확인했다.

- N05~N08/N19의 ‘사건과 무관/핵심 단서가 아님’과 N9 목록 안내가 제작자의 답을 노출한다. 일상 기록은 유지하고 관찰 내용만 남긴다.
- B13/B19/B21/B22/B24 등의 원본 자료에 ‘이것만으로 확정 불가’라는 추리 해설이 이미 적혀 있다. 사실·날짜·발신자를 보존하고 해석은 피드백으로 옮긴다.
- 효은이 휴대폰을 직접 반환하지 못했다는 사실과 사칭 동기가 떨어져 있다. 기존 인정 내용을 연결해 물리적 전달의 한계를 명시한다.
- 최종 재구성의 ‘원본을 돌려달라고 요구했다’는 구체적 발언이 앞선 증거에 없다. 입증된 행동과 계약상 동기 해석을 구분한다.
- B에서11/02의 행정실·경찰 기록이 뒤늦게 나타나는 맥락을 짧게 안내한다.

## 보존 기준

- 범인과 피해자, 점수 조작·사칭·사망 사건의 관계,11월1일행적, 검거와 후일담을 유지한다.
- A 필수7개·선택3개, B 필수6개, 기존 문서·대화·사진·일상 기록을 보존한다.
- 암호, 점수표 비교, 사진 확대, 보관, 자동 저장, 수동 저장·불러오기·취소·초기화 기능을 유지한다.
- 기존에 해결한 추리를 새 형식으로 다시 풀도록 강요하지 않는다. 저장 형식을 호환하고 신규 입력도 저장한다.
- 새로운 범인·숨겨진 공범·근거 없는 반전을 추가하지 않는다.

## 개선 후 통과해야 할 검사

1. HTTPS 새 게임에서 상황 소개→일상 부탁→음원 재생→약속 경과→알림 확인이 순서대로 진행된다.
2.17번/온유를 조사하라는 부탁이 대사·파일·보관 요약에 남지 않는다.
3. A7+선택3, B6, 원본 확보와 최종 순서 재구성, TRUE END를 실제 UI로 완료한다.
4. 오답·근거 누락·잘못된 시간순·미열람 상태가 정답 진행을 만들지 않는다.
5. 원문 재열람·보관·수동 복원·취소·자동 복구·완료 저장 호환을 확인한다.
6.360/390/430px 세로와 낮은 가로 화면에서 본문·버튼·게임 메뉴·선택 상태에 접근 가능하다.
7. 실제 파일 응답과 게임 콘솔 오류를 확인하고 미검증 범위는 별도로 남긴다.

기존 플레이 증거: `qa-before/`의 홈·평가표·A완료·최종추리·TRUE END와 `v13-playthrough-transcript.txt`.

## 검토의 한계와 출시 판단

현재 검토는 제작 측 QA다. 실제 신규 이용자가 도움 없이 목표를 이해하고, 스스로 알아낸 단서를 설명할 수 있는지는 별도 관찰이 필요하다. 수정 후 기능 검사가 통과하더라도 ‘상업성 검증 완료’로 표현하지 않는다. 이 보고서는 수정과 검증의 기준이며, 수정 후 결과는 별도 문서에 기록한다.
